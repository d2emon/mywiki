# Детальный план написания программного кода для игры «Курьер из Будущего»
*(Для программистской команды с использованием Unreal Engine 5 и C++)*

## **1. Архитектура проекта**  
### **1.1. Выбор инструментов и технологий**  
- **Движок**: Unreal Engine 5 (с акцентом на Nanite, Lumen, Niagara для визуальных эффектов).  
- **Языки**:  
  - C++ для ядра игры (механики, ИИ, системы данных).  
  - Blueprints для быстрого прототипирования и настройки контента.  
- **Управление версиями**: Git + Git LFS (для больших файлов).  
- **Бэкенд**: Для мультиплеера (если будет) — Photon Engine или собственная реализация на C++.  

### **1.2. Модульная структура**  
Проект разбивается на модули для параллельной работы:  
1. **TransportSystem** (логика транспорта).  
2. **AICore** (ИИ пассажиров и NPC).  
3. **QuestSystem** (квесты и диалоги).  
4. **CityBuilder** (генерация и управление городом).  
5. **UI** (интерфейсы).  
6. **SaveLoad** (система сохранений).  

## **2. Этапы разработки**  
### **Этап 1: Базовый каркас (2 месяца)**  
- **Задачи**:  
  1. Настройка проекта в UE5, подключение базовых плагинов (Niagara, Chaos Physics).  
  2. Реализация движения транспорта по маршрутам:  
     - Классы `Vehicle` (родительский) → `Bus`, `Tram`, `Metro`.  
     - Система путей: Spline-маршруты с учетом расписания.  
     - Физика столкновений (Chaos Vehicle System).  
  3. Прототип интерфейса:  
     - Миникарта, таймер, индикатор заданий (UMG).  
  4. Система времени:  
     - Игровые сутки = 60 реальных минут, динамическая смена дня и ночи.  

- **Результат**: Автобус едет по маршруту, игрок может садиться/выходить, видит базовый UI.  

### **Этап 2: ИИ и динамические события (3 месяца)**  
- **Задачи**:  
  1. **ИИ пассажиров**:  
     - Реализация поведения через Behavior Trees (BT) и Blackboard:  
       - Пассажиры идут к остановкам, садятся в транспорт, реагируют на задержки.  
       - Система «настроения»: если автобус опаздывает, пассажиры возмущаются.  
     - Настройка Crowd Simulation (MassAI в UE5).  
  2. **Динамические события**:  
     - Пробки: алгоритм расчета задержек на основе плотности трафика.  
     - Аварии: случайные триггеры, влияющие на маршруты.  
  3. **Интеграция с TransportSystem**:  
     - Транспорт подстраивает скорость и маршруты в реальном времени.  

- **Результат**: Пассажиры двигаются по городу, реагируют на события, транспорт адаптируется к пробкам.  

### **Этап 3: Квесты и взаимодействия (3 месяца)**  
- **Задачи**:  
  1. **QuestSystem**:  
     - Класс `Quest` с параметрами: цель, награда, ветвление.  
     - Диалоговая система:  
       - Деревья диалогов (DataTable + JSON).  
       - Интеграция с UI (выбор реплик, индикаторы задач).  
  2. **Взаимодействие с NPC**:  
     - Компонент `Interactable` для объектов и персонажей.  
     - Мини-игры (например, взлом терминала через Blueprints).  
  3. **Система репутации**:  
     - Влияние выбора игрока на отношение фракций («Бессмертные», горожане).  

- **Результат**: Игрок может брать квесты, общаться с NPC, влиять на сюжет.  

### **Этап 4: Город и оптимизация (3 месяца)**  
- **Задачи**:  
  1. **CityBuilder**:  
     - Генерация районов: префабы зданий, алгоритмы расстановки (Procedural Mesh Generation).  
     - LOD-система для оптимизации рендеринга.  
  2. **Нагрузочное тестирование**:  
     - Оптимизация Draw Calls, Occlusion Culling.  
     - Работа с Nanite для статичной геометрии.  
  3. **Интеграция ассетов**:  
     - Импорт 3D-моделей транспорта и зданий, настройка материалов.  

- **Результат**: Город работает на 60 FPS при высокой плотности объектов.  

### **Этап 5: Полировка и финальные системы (2 месяца)**  
- **Задачи**:  
  1. **SaveLoad**:  
     - Сериализация данных: прогресс квестов, позиция игрока, репутация.  
     - Использование UE SaveGame System.  
  2. **Голосования и фидбек**:  
     - Интеграция Steamworks API (достижения, облачные сохранения).  
  3. **Финальная сборка**:  
     - Упаковка проекта, настройка графических пресетов (Low/Medium/High).  

- **Результат**: Готовая к релизу версия с сохранениями и достижениями.  

## **3. Распределение задач в команде**  
- **Программист 1**: TransportSystem + физика.  
- **Программист 2**: ИИ пассажиров + динамические события.  
- **Программист 3**: QuestSystem + диалоги.  
- **Программист 4**: CityBuilder + оптимизация.  
- **Программист 5**: UI + интеграция ассетов.  

## **4. Методологии и стандарты**  
- **Code Review**: Еженедельные проверки через GitHub Pull Requests.  
- **Документация**:  
  - Doxygen для C++ (описание классов и методов).  
  - Confluence для дизайна систем.  
- **Тестирование**:  
  - Юнит-тесты (Google Test Framework).  
  - Интеграционные тесты для квестов и ИИ.  

## **5. Риски и решения**  
- **Риск**: Сложная интеграция транспорта и ИИ.  
  - **Решение**: Использовать UE Chaos Vehicle + MassAI.  
- **Риск**: Низкий FPS в густонаселённых районах.  
  - **Решение**: LOD + Level Streaming + оптимизация текстур.  

## **6. Пример спринта (2 недели)**  
**Цель**: Реализовать систему пробок.  
- **Задачи**:  
  1. Написать класс `TrafficManager`, отслеживающий плотность транспорта.  
  2. Интегрировать с `Vehicle` (снижение скорости при пробках).  
  3. Добавить визуальные эффекты (Niagara — дым из машин).  
  4. Протестировать на маршруте №101.
